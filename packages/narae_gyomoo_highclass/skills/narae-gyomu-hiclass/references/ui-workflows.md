# 실제 화면 경로와 입력 구조

2026-10-15 PC 웹 교직원 계정에서 확인했다. 아래는 관찰 근거이며 고정 API나 영구 선택자 계약이 아니다. 실행 때 현재 화면과 대조한다. 실제 글·대화·개인 식별자는 포함하지 않는다.

## 로그인·클래스

- <https://www.hiclass.net/> → `선생님, 교직원 로그인 하기` → `/login/teacher/v2`.
- 로그인 방식은 `i-Scream 아이디로 시작하기`, `구글로 시작하기`, `Apple로 시작하기`; `나의 SNS 계정 찾기`도 있다.
- 로그인 완료 홈은 `/main/home`. `선생님` 표시와 `나의 클래스/학교` 카드가 보였다.
- 홈 안내 팝업은 `닫기`로 종료할 수 있었다. `더 이상 보지 않음` 설정을 바꿀 필요는 없다.
- 클래스 카드와 학교 카드를 구별한다. 클래스 내부 상단에서 학교·학급·연도·선생님·구성원 수를 대조한다.
- 클래스 경로는 `/main/clazzes/<동적 식별자>`, 알림장은 뒤에 `/note/<동적 식별자>`가 붙었다. 실제 식별자를 저장하지 않고 현재 UI로 이동한다.
- 왼쪽 게시판: `최근 게시글`, `알림장`, `앨범`, `자유게시판`, `과제`. 수업관리: `출결 알리기`, `설문·투표`, `학교 양식 신청서`, `푸시 보내기`. 단순 조회에 관리자 설정·초대·구성원 변경은 필요하지 않다.

## 알림장 조회

1. 클래스 왼쪽 `알림장`을 선택한다.
2. placeholder `게시글 검색`, 검색 범위 `전체` 메뉴, `검색` 버튼이 있다. 상단 전역 검색과 중복될 수 있으므로 게시판 범위로 식별한다. 검색어·상태 탭·조회 범위를 기록한다.
3. 상태 탭은 `전체`, `발송완료`, `임시저장`, `예약`. 필독/상단 글 때문에 첫 글이 최신 글이라고 단정하지 않는다.
4. 제목·작성일·수신대상·본문·읽음 수가 목록에 함께 나타났다. 본문이 접근성 트리에서 빠지면 DOM 스냅샷을 사용한다. 이미 본문이 보이면 추가로 열 필요는 없다.
5. `하이톡 공유`, `판서로 수정`, `게시글로 수정`, `스크랩`, `인쇄하기`는 별도 동작이다. 조회 요청에 누르지 않는다.

여러 글에 같은 이름의 버튼이 있다. 대상 제목·날짜를 찾고 해당 글 안으로 범위를 좁힌다. 임의의 첫 번째 `더보기`·`N명 읽음` 버튼을 누르지 않는다.

## 알림장 작성

`알림장` → **게시글 쓰기** → 이름이 `알림장`인 dialog.

| 요소 | 관찰된 구조 |
| --- | --- |
| 제목 | textbox/textarea, placeholder `제목을 입력하세요.` |
| 본문 | dialog 안 `div[contenteditable="true"]`; 별도 숨은 textarea와 혼동하지 않기 |
| 서식 | `폰트 크기`, `굵게`, `밑줄`, `텍스트 색상`, `배경색`, `서식 제거` |
| 미디어 | `이미지 삽입`, `동영상 삽입` |
| 첨부 | `묶음 사진올리기 (앨범)`, `문서 파일` 영역; 서로 다른 file input |
| 표시 | checkbox `필독`, `상단공지` |
| 자동 문구 | switch `오늘의 안전수칙 사용`, `문구관리` |
| 수신자 | checkbox `학부모`, `학생`; 확인 당시 둘 다 선택됨 |
| 예약 | switch `예약`; 상세 날짜·시간 조작은 이번 제작에서 미검증 |
| 하단 | `취소`, `임시저장`, **등록** |

현재 DOM이 일치하고 실제 입력이 허가된 요청에서만 적용할 수 있는 예:

```js
const editor = tab.playwright.getByRole('dialog', {name: '알림장', exact: true});
await editor.getByRole('textbox', {name: '제목을 입력하세요.', exact: true}).fill(title);
const body = editor.locator('[contenteditable="true"]');
// 현재 DOM에서 본문이며 유일한 요소임을 확인한 뒤 입력한다.
await body.fill(message);
// 다음은 학부모만 수신대상으로 명시된 경우다.
await editor.getByRole('checkbox', {name: '학부모', exact: true}).check();
await editor.getByRole('checkbox', {name: '학생', exact: true}).uncheck();
// 새 스냅샷으로 대조한다. 이 예에는 저장·등록 동작이 없다.
```

실제 입력은 제작 계정에서 시험하지 않았다. 다른 UI에서는 현재 편집기를 확인한다. 빈 양식 탐색은 dialog 안 `취소`/`닫기`로 마치고 사라졌는지 확인한다. 기존 초안이 있으면 임의로 닫지 않는다.

## 읽음 현황·푸시

알림장의 **N명 읽음**은 `푸시 보내기` dialog를 열었다.

- 이름/태그 검색, 학반 태그 필터, `읽지 않은 구성원`, `전체`, `학부모`, `학생` 체크박스가 있다.
- 구성원별 읽은 시각/`읽지않음`을 볼 수 있다. 로딩 중 0명·비활성 상태를 최종 결과로 보고하지 않는다.
- `푸시 내용 입력`, 내용 textbox, `총 N명`, **보내기**가 있다. **미열람 구성원이 자동 선택되고 기본 안내 문구도 이미 채워질 수 있다.** 입력하지 않아도 전송 버튼이 활성화될 수 있다.
- 화면에는 5분 간격 전송 가능, 상대 알림 설정에 따른 수신 제한 안내가 있었다. 실제 안내를 우선한다.
- 조회는 현황만 확인하고 `닫기`로 끝낸다. 미열람자 재알림은 수신자·문안을 별도 발송 대상으로 대조한다. 클래스 수업관리의 `푸시 보내기`도 발송 기능이다.

## 하이톡·1:1 연락

1. 상단 `하이톡`은 별도 탭/창 **`/hitalk`**을 열었다. 기존 클래스 화면이 변하지 않았다고 연타하지 않는다. 탭 목록에서 새 창을 찾아 선택한다.
2. 좌측 주요 버튼: `대화상대`, `대화목록`, `예약발송 목록`, `투표 관리`. `상담 가능 시간 설정`, `차단 목록`도 있다. 연락 조회에 설정 변경은 필요하지 않다.
3. `대화목록` 검색 placeholder는 `대화방 검색`. 상대·최근 메시지·날짜가 보인다. 기존 방이 있으면 클래스·상대를 확인하고 재사용한다. `(알수없음)` 방은 상대를 추측하지 않는다.
4. `대화상대` 검색은 role `combobox`, placeholder `이름, #태그 검색`. 클래스별 구성원과 `공지하기` 영역이 있다. 표시명의 학생·보호자를 모두 대조한다.
5. 기존 1:1 방 상단에 상대·클래스·참여 인원수가 나타났다. 요청에 필요한 날짜·내용만 읽는다. 열람으로 읽음 상태가 반영될 수 있으므로 읽음 변경 금지 요청이면 방을 열기 전에 멈춘다.
6. 본문 입력은 `[contenteditable="true"]`이며 textbox 역할이 없었다. 현재 방의 유일한 편집기인지 확인한다. **Shift + Enter키를 누르면 줄바꿈됩니다**라는 시각 안내가 있었다.
7. 첨부: `사진`, `영상`, `문서`, `스티커`. 하단: `예약메시지`, **보내기**. 제작 시 빈 입력 상태의 보내기는 비활성이었다. `대화 저장하기`/`다운로드`는 별도 내보내기 기능이다.

## 일괄·단체

하이톡 `대화상대` → `공지하기` 영역의 **해당 클래스 행**에서 선택한다. 클래스가 여러 개면 버튼 이름만으로 고르지 않는다. `사용안내`에서 확인한 의미:

- **일괄**: 동일 내용을 각 개인 **1:1 대화방**으로 전송.
- **단체**: 여러 명이 들어간 공지방이며 **선생님만 전송** 가능. 학부모 자유 대화방으로 안내하지 않는다.

`일괄` → dialog **일괄메시지 작성**:

- 검색, `태그 필터`, checkbox `전체`·`학부모`·`학생`, 개별 구성원 선택.
- textbox `메시지를 입력해주세요.`, 첨부 `사진`·`동영상`·`파일`.
- 최종 **N명 보내기**. 선택 0명일 때 비활성이었다. 명단·체크 상태·인원수를 대조한다.
- 오류 시 일부 전송 가능성을 확인하고 전체 재전송하지 않는다. 조회 탐색은 입력·선택 없이 dialog `닫기`로 마친다.

`단체` → dialog **단체방 만들기**:

- textbox `단체방 이름을 입력해주세요.`에 클래스 기반 기본 방 이름이 있었다.
- switch `단체방 알림설정`은 켜져 있었다. 검색·태그·역할/개별 수신자 선택 제공.
- `취소`, **만들기**. 메시지 작성이 아닌 **방 생성 단계**다. 기존 방이 있는데 중복 생성하지 않는다.
- 방 생성 이후 최초 메시지 입력·전송은 미검증이다. 허가된 실행에서 현재 UI를 관찰한다. 전송 전 정지 요청에 방 생성까지 포함되는지 불명확하면 이 선택 화면에서 멈춘다.

## 예약메시지

기존 대화 하단 `예약메시지` → dialog **예약 메시지 작성**:

- 버튼 `예약 시간을 선택해주세요.`
- textbox `메시지를 입력해주세요.`
- 첨부 `사진`, `동영상`, `파일`
- 최종 **예약하기**; 빈 상태에서는 비활성이었다.

시간 선택 세부 UI·실제 등록은 미검증이다. 허가된 실행에서는 대상 대화·현지 날짜/시간·과거 시각 여부를 대조하고 등록 후 `예약발송 목록`의 대상·내용·일시를 확인한다. 알림장 예약 switch와 하이톡 예약을 같은 양식으로 취급하지 않는다.

## 검증 범위·참고

로그인·학급 진입·알림장/열람 현황·기존 하이톡 대화 조회와 빈 알림장/일괄/단체/예약 양식을 확인했다. **실제 내용 입력, 업로드, 저장, 방 생성, 게시·발송·예약은 미실행**이다. 성공·오류 결과는 실제 허가된 실행에서 확인해야 한다.

홈의 공식 이용가이드 링크는 <https://hiclass.notion.site/d7d429af394b4d8b82cdd52acfb549dc>였다. 가이드 본문은 이번 제작에서 확인하지 않았다. 학교·권한·개편 차이는 현재 하이클래스 화면을 우선한다.
