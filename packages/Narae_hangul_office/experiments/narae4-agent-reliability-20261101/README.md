# 나래4 오피스 에이전트 실행 보완

이미지를 실제로 읽은 뒤 같은 `read_image`를 반복하는 문제와, 문구 한 곳을 바꾼 뒤 완료를 판단하지 못하는 문제를 보완한다. 모델 가중치는 기존 v1을 유지하며 추가 학습을 수행하지 않는다.

- 명시한 그림 파일을 한 건씩 읽고, 모든 대상의 실제 이미지 입력이 준비되면 분석 답변으로 넘어간다. 여러 그림 비교는 모든 명시 파일을 읽는다. 문서 작성·전송 등이 섞인 요청에는 이 종료 절차를 적용하지 않는다.
- 긴 문맥을 줄일 때 실제 이미지와 현재 사용자 요청을 유지한다. 이미지가 문맥 한도를 넘으면 기존 한도 오류를 반환하며 읽은 그림을 몰래 버리지 않는다.
- 특정 문구만 바꾸라는 요청은 실제 본문에서 유일한 대상을 확인하고 최신 해시로 수정한다. 저장 해시와 재읽기 해시, 요청 문구의 변경 및 다른 문단 텍스트 보존을 대조한 뒤 종료한다. 같은 문구가 여러 번 나오거나 복합 작업이면 자동으로 한 곳을 선택하거나 전체 완료로 보고하지 않는다.

이 시험은 **실행기를 포함한 실제 v1 모델·이미지·HWPX 시험**이다. 직접 모델의 다음 행동 정확도, 공개 OfficeBench 점수, 실학교 기초 10과제 합격과 구분한다. 학교에 로그인하거나 시험 메시지·기안을 만들지 않는다. 가상 그림의 기대값은 평가기에만 있고 모델 입력에는 그림과 사용자 질문만 전달한다.

```powershell
node experiments/narae4-agent-reliability-20261101/run.cjs D:/Codex/training/narae4-agent-reliability-reproduction
```

비어 있는 새 폴더와 설치된 v1 모델이 필요하다. `NARAE_AI_MODELS`로 기존 모델 폴더를 지정할 수 있다. PNG 생성에는 Pillow와 Windows 맑은 고딕을 사용한다. 작업은 순차 실행하며 종료 때 자신의 모델만 내린다. 출력 폴더에는 문항별 도구 호출·답변·판정, 실제 문서 전후 inspect, 모델·소스·그림 SHA256을 보존한다. 모델·임시 파일은 Git에 넣지 않는다.

첫 준비 실행 r1은 격리된 작업 폴더에 모델 위치를 연결하지 않아 모델을 시작하지 못했다. 실행기의 모델 경로를 수정한 뒤 새 폴더에서 다시 실행한다. 이 준비 오류를 모델 성능 점수로 계산하지 않는다.

## 최종 확인

최종 소스를 고정한 r3 실행은 **4/4**다. 평가 중 소스·평가기 변경이 없었고 기존 v1 어댑터의 SHA256도 유지됐다. 개발 중 r2 역시 네 흐름을 통과했으나 종료 조건을 추가 보완했으므로, 결과 파일은 최종 소스로 다시 실행한 r3만 제공한다.

| 실제 모델·도구 작업 | 결과 |
| --- | --- |
| 새 가상 안내 그림의 장소·금액·시작·종료 읽기 | 2/2, 파일마다 실제 읽기 1회 |
| 두 가상 그림의 장소·금액 비교 | 1/1, 두 파일 모두 읽기 |
| 실제 HWPX의 장소 한 곳 수정·저장·재읽기 | 1/1, 편집 1회, 다른 텍스트·서식 유지 |
| 전체 회귀시험 `npm test` | 245/245 |

이미지의 정답을 모델 인자에 넣거나 정규식으로 답변을 생성하지 않았다. 문서의 유일한 변경 대상을 제한하고 저장본을 확인하는 실행기 보정은 포함된다. 두 그림 비교 약 60초, 한 곳 문구 수정 약 22초가 걸렸으며 PC 부하에 따라 달라진다. [실행 결과](results/report.json), [문서 전](results/native-before.json), [문서 후](results/native-after.json)에서 실제 도구 호출과 검증 자료를 확인할 수 있다. 이 작은 회귀 묶음의 통과가 전체 교무 업무의 자율 수행 능력을 입증하지는 않는다.
