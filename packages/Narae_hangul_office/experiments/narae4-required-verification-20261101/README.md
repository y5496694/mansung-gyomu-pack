# 필수 업무 10개 추가 검증

사용자 지정 계약 `narae-office-basic-10-v1`의 전체 상태를 검증한다. 공개 OfficeBench나 모델 단독 점수가 아니다. 설치된 **나래4 v1**, 같은 앱의 제한된 실행기, 모의 외부 서비스를 함께 사용하며 새 가중치 학습은 하지 않는다.

## 시험 범위

- 로그인: 시험용 비밀을 Windows DPAPI로 등록하고 실제 보안 문서 읽기·암호 입력 경로와 독립 Chrome을 실행한다. 외부 요청은 시험 도메인의 응답으로만 대체한다. 비밀 원문·인증서·CLIXML은 결과 저장소에 넣지 않는다.
- 소통 탐색: 101개 쪽지, 101개 대화방, 201개 메시지에서 모든 페이지와 기간 안의 본문 300개를 확인한다. 기간 밖 자료, 마지막 페이지의 일치 본문, 방 이름에만 검색어가 있는 반례, 변경·취소를 포함한다.
- 전송: 실제 `OfficeIntegrations`와 원본의 수신자·미리보기·한 번만 적용하는 경로를 사용한다. CBE 백엔드는 상태를 가진 모의 기록으로 대체한다. 동명이인 중 현재 소속으로 한 명을 고르고 쪽지·대화 원문과 단일 전송 기록을 검사한다.
- 공문: 모의 브라우저 목록·WXS 읽기 어댑터에서 담당 문서 두 페이지, 공람대기·완료 각각 두 페이지, 긴 본문과 모든 첨부를 읽는다. 인증 대기 첫 문서는 보존·미확인으로 표시하면서 나머지 문서를 계속 읽는 반례도 별도로 실행한다. 실제 WXS 네이티브 열람 호환성을 이 어댑터 시험으로 인증하지 않는다.
- 타인 복무: 실제 Chrome·localhost 서버에서 코드값이 다른 소속 선택란, 정확한 성명·날짜, 두 결과 페이지를 조회한다. 다른 학교·다른 날짜의 결과를 성공으로 보고하지 않는 회귀시험도 실행한다.
- 출장·연가·조퇴: [별도 실행기](../narae4-required-bench-20261101/run.cjs)를 같은 소스로 다시 실행한다. 실제 브라우저·확인창과 localhost 서버를 사용하며 신청·결재선·서버 행·중복을 대조한다.
- 기안: 이번에는 원문을 보존한 임시저장·재조회 smoke만 실행했다. **실제 WXS 양식·필드 닫힘·줄 정렬·화면 검수·서버 첨부·문서처리·최종 상신은 미검증**이므로 이 과제는 합격으로 계산하지 않는다.

탐색과 일부 조회 단계는 `bounded-rule`, 로그인·전송·근거 선택 등은 실제 가중치 추론을 사용한다. 각 기록의 `modelRequests.route`와 통합 요약의 `routes`로 구분한다. 원문 기록의 `actualLocalWeights`는 실제 모델을 연결한 실행 설정이며 모든 단계에서 추론했다는 뜻이 아니다. 실제 학교에는 로그인하거나 시험 쪽지·기안·복무를 등록하지 않는다.

## 발견하고 고친 문제

1. 대화방 이름에만 검색어가 있어도 본문 검색 결과에 포함됐다. 대화의 검색 조건을 메시지 본문에 적용한다.
2. 본문·첨부를 요약하면서 문서별 상태·현재 결재자가 빠졌다. 같은 제목의 관찰한 목록 행을 원문 근거와 함께 보존한다.
3. 공람 첫 문서가 인증 대기이면 다음 페이지로 넘어가지 않았다. 인증 대기 항목을 미확인으로 유지하면서 나머지 페이지를 확인한다.
4. 감싼 선택란의 선택지들이 필드명에 붙어 소속 선택을 놓쳤다. 필드명과 선택지를 분리하고 코드값·표시 이름을 대조한다. 복무 결과 행의 요청 소속·일자가 다르면 완료로 처리하지 않는다.

초기 실행 r1의 실패 기록을 보존하고 수정 후 r2를 별도 폴더에 실행했다. 로그인 시험 준비에서 PowerShell 모듈 자동 로딩이 실패한 것은 명시적인 시스템 모듈 로딩으로 해결했다. 실제 개인 로그인 설정을 변경하지 않았다.

## 재현

Windows, 설치된 나래4, Chrome과 새 출력 폴더가 필요하다. 메모리를 고려해 아래 두 모델 시험과 전체 회귀시험은 차례로 실행한다.

```powershell
node experiments/narae4-required-verification-20261101/run.cjs D:/Codex/training/required-verification-new
node experiments/narae4-required-bench-20261101/run.cjs D:/Codex/training/required-submission-new
node experiments/narae4-required-verification-20261101/combine.cjs D:/Codex/training/required-combined-new D:/Codex/training/required-verification-new D:/Codex/training/required-submission-new
node src/cli.cjs bench D:/Codex/training/required-combined-new/run.json
```

통합기는 두 실행의 소스·어댑터 해시와 실행 중 불변성을 검사하고 모든 원문 근거의 해시를 재확인한다. 기안이 미검증이므로 마지막 전체 판정 명령의 종료코드 1이 정상이다. 부분 통과 기록은 `bench import 실행결과.json`으로 연결할 수 있으며 실환경 통과로 바뀌지 않는다.

## 검증 결과

수정 후 추가 시험 r2와 같은 소스의 연가·조퇴·출장 재시험 r3를 통합한 결과는 **모의 9/10 과제 통과**다. 두 실행 모두 소스·평가기·화면 자료가 실행 중 바뀌지 않았고 기본 어댑터도 변경하지 않았다. 실제 학교 환경은 전 항목 미검증이며 `releasePassed:false`다.

최종 [전체 회귀시험](results/regression.json)은 **264/264 통과**, 실패·생략 0개다. 수정한 런타임 다섯 파일은 기존 설치본과 대조·백업 후 적용했고 앱의 벤치 기록도 모의 9개 통과·실환경 미검증으로 갱신했다. 사용 중인 앱·문서·학교 로그인 세션은 재시작하거나 변경하지 않았다. 실행 중이던 앱은 다음 실행부터 수정된 런타임을 사용한다. 시험 모델·브라우저는 모두 종료했다.
