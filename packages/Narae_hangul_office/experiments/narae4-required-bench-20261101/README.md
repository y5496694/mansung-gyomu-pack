# 필수 업무 벤치 기준 실행기 보완

후속 전체 상태는 [추가 통합 검증](../narae4-required-verification-20261101/README.md)을 참고한다. 아래 결과는 최초 연가·조퇴·출장 묶음의 기록이다.

앱의 나래 에이전트 사이드바에 **필수 업무 벤치 10개**를 추가했다. 기존 `narae-office-basic-10-v1` 계약을 그대로 읽으며 모의·실환경 결과를 분리한다. 실행 기록과 근거 JSON의 해시를 재검사하므로 과거에 불러온 기록이나 근거가 바뀌면 통과 상태를 유지하지 않는다. 일반 코드 회귀시험이나 그림 시험 점수는 이 목록의 통과 수에 포함하지 않는다. 에이전트가 상태를 물을 때도 실제 기록으로 정해진 결과를 표시한다.

필수 과제 6번은 현재 계정의 **업무담당확인** 목록으로 연결하고 본문·첨부까지 읽도록 보완했다. 상태만 확인하거나 본문을 열지 말라는 요청은 그대로 따른다. 과제 9·10번은 나래4의 입력 준비 → 개인결재선 확인 → 요청값·순서 대조 → 화면 지문 검증 → 실제 확인창 처리 → 같은 서버 신청 행의 재조회 절차를 연결했다. 출장의 유형·교통·여비도 실제 요청값으로 대조한다. 여러 날의 연가는 종료일을 별도로 확인하며 날짜 마스크에는 실제 관찰한 달력 버튼을 사용한다.

나이스의 승인요청에서 기안문서상신 화면을 여는 절차는 [인천교육청 공개 매뉴얼 5쪽](https://www.ice.go.kr/upload/ice/na/bbs_2084/2023/12/709eb6a816bcbd0df589cefc3fc63f4f.pdf#page=5)을 참고했다. 실제 화면에서 근무상황신청 또는 출장신청의 확인된 버튼만 준비 단계로 취급한다. 최종 상신은 기존 브라우저의 문서·화면 지문·정확한 확인창·중복 방지 검증을 유지한다. 현재 계정·권한·실제 화면이 다른 경우 미확인으로 남기며 새로운 주소·결재자·문구를 만들지 않는다.

## 검증 방법

`tests/neis-submit.test.cjs`는 실제 Chrome과 localhost 서버로 연가·조퇴·출장을 시험한다. 날짜가 다른 서버 행, 삭제 확인창, 다른 결재자 순서에서는 완료하거나 중복 상신하지 않아야 한다. `tests/office-bench-desktop.cjs`는 격리된 Electron 앱에서 10개 카드, 미검증 표시, 목록 복사, 새로고침, 최소 창 크기와 닫기를 확인한다.

아래 시험은 **기존 나래4 v1 가중치**가 실제 오피스 에이전트와 브라우저를 사용한다. 서버와 신청은 가상이며 localhost 외 네트워크를 차단한다. 실제 학교에 로그인하거나 쪽지·문서·복무를 쓰지 않는다. 이 실행기를 포함한 결과를 모델 단독 판단 능력이나 공개 OfficeBench 점수로 설명하지 않는다. 추가 가중치 학습은 하지 않는다.

```powershell
node experiments/narae4-required-bench-20261101/run.cjs D:/Codex/training/narae4-required-bench-reproduction
narae-office bench D:/Codex/training/narae4-required-bench-reproduction/run.json
narae-office bench import D:/Codex/training/narae4-required-bench-reproduction/run.json
```

새 폴더와 설치된 나래4가 필요하며 모델은 한 번에 하나씩 실행한다. 출력에는 실제 도구 관찰·확인창·가상 서버 기록과 계약에 맞는 `run.json`·판정이 남는다. 이번 묶음의 계약 대상은 **출장 1변형, 연가·조퇴 2변형**이다. 다른 8개 필수 과제에는 완료 증거를 만들지 않는다. 전체 10개와 실환경 합격은 별도로 검증해야 한다.

## 실제 나래4 실행 결과

기존 v1 모델로 **연가·조퇴·출장 3/3 흐름**을 통과했다. 평가 중 소스·평가기·화면 fixture 변경이 없었고 기본 어댑터도 바꾸지 않았다. 입력값과 실제 결재선, 관찰한 확인창 수락, 서버의 동일 신청 행 및 중복 방지를 계약 검사로 대조했다. 최초 준비 실행은 Windows ESM 파일 URL 처리 오류로 모델을 시작하지 못했으며, 파일 URL을 수정한 r2 실행의 결과만 제공한다.

| 필수 과제 | 모의 계약 판정 | 실환경 |
| --- | --- | --- |
| 9. 출장 상신 | 국내출장 변형 검사 통과 | 미검증 |
| 10. 연가·조퇴 상신 | 연가·조퇴 두 변형 검사 통과 | 미검증 |
| 1~8 | 이번 계약 실행의 검증 대상 아님 | 미검증 |

따라서 이번 계약 기록은 **모의 2/10 과제 통과**, `fullTenTaskPass:false`, `releasePassed:false`다. 이전의 조회 흐름·문서 시험·코드 회귀시험 점수를 보태 10/10으로 표시하지 않는다. 앱에 같은 기록을 불러와 모의·실환경 상태를 구분한다. [실행 요약](results/summary.json), [계약 판정](results/grade.json), [연가](results/연가.json), [조퇴](results/조퇴.json), [출장](results/출장.json)에 실제 호출·확인창·가상 서버 기록이 있다.

최종 `npm test`는 **258/258**이다. 설치본의 격리된 Electron 창에서도 목록 표시·복사·새로고침·기록 불러오기·미검증 구분·최소 창 크기·닫기를 확인했다. 불러온 기록의 출장·연가/조퇴 모의 통과와 실환경 미검증 표시를 화면에서 대조했다. 모델 서버와 시험용 앱·브라우저는 종료했으며 사용자의 기존 앱을 재시작하지 않았다. 설치본의 새 화면과 실행 경로는 다음 앱 실행부터 적용된다.
