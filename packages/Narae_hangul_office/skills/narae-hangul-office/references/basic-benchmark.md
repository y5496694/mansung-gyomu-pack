# 나래오피스·나래4 필수 업무 벤치

`narae-office bench`로 `narae-office-basic-10-v1` 계약을 읽는다. 사용자 요청에 따라 열 가지 과제는 전부 필수이며 미지원·미검증·부분 성공도 불합격이다. 최근 몇 건 조회나 초안 준비를 전체 탐색·최종 상신 성공으로 대체하지 않는다.

| --- | --- | --- |
| 1 | 보안 문서 로그인·시스템 진입 | DPAPI·비밀 비노출, 포털·나이스·에듀파인 실제 화면 |
| 2 | 6개월 소통 제출 후보 탐색 | 달력 6개월, 쪽지 모든 페이지·모든 방의 대화 본문, 변경·취소·출처 |

## 다른 PC의 설정

개인 인증서는 해당 Windows 계정의 기존 DPAPI 보안 문서를 사용한다. 보안 문서 등록은 업무포털 스킬의 `certificate-profile.ps1`을 따른다. `narae-office school-status`는 비밀값 없이 등록·인증서 위치만 점검한다. 실제 암호를 채팅·평문 JSON·명령 인자에 넣지 않는다.

충북 기본 주소를 사용하는 경우 추가 설정 없이 기존 기본 보안 문서를 찾는다. 다른 교육청 또는 기존 보안 문서의 위치를 지정할 때는 로컬 설정 JSON을 작성하고 `narae-office school-config 설정.json`을 실행한다.

```json
{
  "region": "해당 교육청",
  "portalUrl": "https://공식적으로-확인한-업무포털-주소/",
  "credentialsPath": "D:/사용자/기존-보안문서.clixml"
}
```

`credentialsPath`는 기존 문서를 명시적으로 지정할 때만 필요하다. `certificateOrigins`는 실제 인증서 프레임의 별도 HTTPS 출처를 확인한 환경에서만 등록한다. 설정은 앱 데이터의 `data/school-profile.json`에 저장된다. 학교·개인 이름·수신자 ID·결재선·인증정보를 공용 코드나 스킬에 고정하지 않는다.

나래4에 “설정된 보안 문서로 업무포털 자동 로그인하고 나이스와 에듀파인에 접속해 줘”라고 요청하면 전용 로그인 도구를 사용한다. 이미 로그인되어 있으면 세션을 재사용한다. 인증서 제출은 한 번만 시도하며 결과 불명 시 자동 재시도하지 않는다. 최초 기기 접근 승인과 브라우저 밖 인증은 사용자 단계다. WXS 추가 인증 창은 별도로 보존한다. 도구가 비어 있거나 실패하면 자동 로그인 완료로 보고하지 않는다.

## 탐색과 상신

“소통 쪽지/대화 6개월 치 제출할 내용을 찾아 목록으로 정리해 줘”는 `gyomu_cbe_archive`를 사용한다. 쪽지는 첫 페이지 날짜 기준점을 고정하고, 대화는 방 목록과 각 방 메시지를 끝까지 조회한다. 검색어가 있으면 메시지 본문에 적용한다. 결과의 `complete`, `unconfirmed`, 날짜·조회 수·원문 근거 ID를 확인한다. 긴 원문과 전체 조회 근거는 작업 폴더의 `나래-소통탐색`에 저장한다. 첨부 내용은 별도 확인 대상이며 후보 목록은 실제 제출 완료 목록이 아니다.

공람 “모두”는 기간을 표시하고 공람대기·공람완료를 같은 조건으로 확인한다. 기간을 지정하지 않았으면 기존 기본값인 최근 한 달을 표시하며 전 기간이라고 말하지 않는다. 인증 대기 문서는 창을 보존하고 미확인으로 남겨 다른 문서를 계속 확인한다. 긴 묶음은 문서별 원문 근거로 나누어 정리한다.

기안은 원본 WXS 절차의 서식·첨부·결재선 검증을 따른다. 기존 상신 도구 이후 내부결재 문서 미리보기와 문서처리는 `gyomu_wxs_final_continue`로 동일 receiptId를 이어 처리한다. 원본 CLI의 지문·동일 문서·중복 방지 검증을 유지한다. 새 상신을 만들거나 기록을 삭제해 재시도하지 않는다. 상신 기록과 신청/문서진행 목록이 일치해야 완료다.

타인 복무는 현재 화면에서 확인한 조회 메뉴·성명·소속·날짜와 결과 표를 사용한다. 동명이인·권한 부족·생략 행·동일 다음 페이지는 미확인이다. 출장 입력 보조가 있어도 실제 출장 화면의 결재 단계와 신청 목록을 검증하지 않았다면 출장 상신 합격으로 보고하지 않는다. 연가·조퇴 준비를 출장 신청 완료로 바꾸어 설명하지 않는다.

## 판정 파일

`narae-office bench 실행결과.json --result 판정.json`은 계약의 모든 변형과 검사를 판정한다. 하나라도 누락되면 종료코드 1이다. 실행결과는 `schema:1`, `contract:"narae-office-basic-10-v1"`, `environment:"synthetic"` 또는 `"live"`, `cases` 배열이다. 각 case는 `task`, `variant`, `checks`를 가진다. 검사에는 `passed:true`와 `evidence`가 필요하며, 각 증거는 `file`, `sha256`, `pointer`(JSON Pointer), `expected`를 가진다. 실제 도구 기록·화면 검토 원문을 근거로 작성하고 값을 임의로 인증하지 않는다. 증거 파일의 해시와 원문 값도 대조한다.

`passed`는 해당 환경의 계약 충족, `releasePassed`는 live 환경의 전체 통과다. 합성 시험 통과를 실학교 처리 실적으로 올리지 않는다. 가짜 공문·출장·연가를 학교 서버에 제출해 벤치 점수를 만들지 않는다. 실제 발송·상신 검증에는 사용자가 지정한 실제 대상·내용·날짜와 기존 실행 권한이 필요하다. 학습 여부와 도구·스킬 보완을 구분하며 프롬프트 보강을 가중치 학습이라고 부르지 않는다.
