# 실제 수행 신뢰도 기록

앱 설치 폴더의 `docs/모델-신뢰도.md`가 계산식과 기록 계약의 원본이다. 모델 선택 화면의 신뢰도는 **성공 ÷ (성공 + 실패·부분 완료)**이며 확인 가능한 요청 건수와 함께 표시한다. 과거 실행기에서 실패한 요청도 포함하고, 실서비스 시험은 실제 정규 업무와 구분해 표시한다. 가상·모의·학습 시험, 결과 미확인·취소, 원본 근거가 변한 기록은 집계하지 않는다. 모델+실행기의 관측값이며 모델 자체의 보정된 확률이 아니다.

각 실제 업무가 끝나면 요청 원문, 실제 응답 또는 도구 오류 응답, 날짜, 모델 alias·어댑터 SHA256, 전체 요청의 결과를 검토한다. 변경 업무는 저장·서버 재조회 등 필요한 결과 근거를 확인한다. 기존 파일과 JSON Pointer·expected 값 및 SHA256을 포함한 `schema:1, records:[...]`를 D:\Codex 아래에 준비한 뒤 다음 스크립트로 로컬 앱 데이터에 추가한다.

```powershell
node <office-root>/scripts/import-model-reliability.cjs D:\Codex\evaluations\검토된기록.json D:\Codex\narae-data\office
```

한 요청의 도구 단계마다 성공을 늘리거나, 나중에 다른 AI가 수동으로 마친 결과를 원래 모델의 성공으로 바꾸지 않는다. 재시도는 독립 실행이 확인된 경우 한 건으로 기록한다. 응답 원문이 없으면 null, 도구 오류만 남았으면 `responseKind:'tool-error'`로 표시한다. 별도 학습 후보의 가중치 성과를 현재 배포 모델에 합산하지 않는다.

원문 기록은 `<app-home>/data/model-reliability.json`에 있고 근거 파일은 사용자 PC에 남는다. 기록과 원문 근거는 Git·소스 ZIP·Hugging Face 공개 대상이 아니다. 앱 UI의 기록 새로고침으로 재검증한다.

사용자가 삭제한 이전 기록은 `removedIds`로 재등록을 막는다. 새 벤치를 추가할 때 이 목록과 집계 기준 변경 사유를 보존하고, 삭제한 원본 묶음을 다시 가져오지 않는다.
