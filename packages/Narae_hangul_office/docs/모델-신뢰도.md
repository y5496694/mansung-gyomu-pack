# 모델별 실제 수행 신뢰도

설정 → AI 연결 → 나래AI에서 각 모델의 **신뢰도** 버튼을 누릅니다. 버튼 왼쪽의 퍼센트는 이 PC에 보관한 실제 수행 목록에서 계산합니다. 목록을 펼치면 날짜, 요청 원문, 응답 원문 또는 도구 오류 응답, 수행 결과 확인 근거를 볼 수 있습니다. 원문이 남지 않은 항목은 미보존으로 표시하며 답변을 재구성하지 않습니다.

계산식은 `성공 ÷ (성공 + 실패·부분 완료) × 100`입니다. 요청 한 건은 도구 단계가 여러 개여도 한 번만 셉니다. 원본 근거가 확인된 실패와 실행기 수정 전의 시도도 포함합니다. 실제 시스템에서 처리한 시험용 업무는 **실서비스 시험**으로 표시합니다. 가상 화면·모의 서버·학습 문제는 제외합니다. 미확인·취소·근거가 바뀌거나 사라진 기록은 분모에도 넣지 않습니다. 확인 건수가 없으면 **미집계**이며 0%로 표시하지 않습니다.

이 수치는 모델과 오피스 실행기가 함께 수행한 관측 결과입니다. 모델 단독 정확도나 미래 업무의 성공 확률을 의미하지 않습니다. 현재 배포 모델의 alias와 어댑터 SHA256이 같은 기록만 집계하며 다른 학습 후보의 성과를 합산하지 않습니다. 모델 식별 정보가 없는 오래된 대화는 현재 선택한 모델의 성과로 추정하지 않습니다.

## 기록 보관과 검토

원문은 앱 데이터 폴더의 `data/model-reliability.json`에 보관합니다. 실제 학교 내용·개인 정보·로컬 근거 파일은 Git, 소스 ZIP, 모델 저장소에 포함하지 않습니다. 새 PC에는 사용자의 실제 기록이 없으므로 미집계로 시작합니다. 대화가 정상 종료됐다는 사실만으로 성공 점수를 자동으로 추가하지 않습니다.

새 실제 수행 기록을 검토한 AI는 요청의 전체 성공 여부와 원본 파일을 확인한 뒤 다음 도구로 추가할 수 있습니다.

사용자가 삭제한 기록의 ID는 `removedIds`에 보존합니다. 이후 새 기록을 가져와도 이 제외 목록과 집계 기준 변경 사유를 유지하며, 삭제된 ID의 재등록은 거부합니다.

요청은 최대 5만 자, 실제 응답은 최대 25만 자를 보관하며 원문 전체가 근거와 일치해야 합니다. 긴 응답을 별도 발췌문으로 바꿔 원문이라고 등록하지 않습니다.

```powershell
node scripts/import-model-reliability.cjs D:\Codex\evaluations\검토된기록.json D:\Codex\narae-data\office
```

입력은 `schema:1`, `records` 배열입니다. 각 항목에는 고유 `id`, `model`, `modelAlias`, `adapterSha256`, ISO `at`, `title`, `environment`(`live-service` 또는 `real-file`), `kind`(`work` 또는 `service-test`), `outcome`(`success`, `failure`, `partial`, `unverified`, `cancelled`), `prompt`, `response`, `verification`, `proofs`가 필요합니다. 원문이 없으면 `prompt`/`response`는 null입니다. 도구 오류만 남았으면 `responseKind:'tool-error'`로 구분합니다.

`proofs`는 절대 `file`, 파일의 `sha256`, `checks:[{pointer,expected}]`로 원본 JSON 값까지 대조합니다. `syntheticOnly:true`, `synthetic:true`, `environment:'synthetic'`인 원본을 실제 성과로 등록할 수 없습니다. 같은 요청의 `id`를 다시 불러와도 건수를 늘리지 않습니다. 신뢰도 창을 열거나 **기록 새로고침**을 누르면 근거를 다시 검사하며 불일치는 미확인으로 바뀝니다. 변경·삭제·상신 업무는 응답의 완료 주장만으로 성공 처리하지 말고 실제 저장·서버 재조회·첨부 대조 등 요청에 필요한 결과를 확인해야 합니다.
