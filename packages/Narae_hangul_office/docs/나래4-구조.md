# 나래4 오피스 에이전트

나래4는 Qwen3.5-2B 문서·시각 모델과 LiquidAI/d1-2B 판단기를 작업에 따라 호출하는 구성입니다. 두 아키텍처의 가중치를 섞거나 나래3 어댑터를 붙인 모델이 아닙니다. sparse MoE 네트워크의 공동 학습과도 구분합니다.

## 다음 행동을 고르는 순서

1. 기존 오피스 작업 계획기가 현재 관찰에서 도구와 인자를 제한합니다.
2. 완전히 정해진 후보가 하나이면 같은 도구 계약으로 실행합니다.
3. 여러 후보가 모두 유효하고 인자 생성이 필요 없으면 d1의 `/v1/systemone`으로 고릅니다. 선택 확률이 0.95 이상일 때만 사용합니다. 이 수치는 교무 업무에서 보정된 성공 확률을 뜻하지 않습니다.
4. 후보가 부족하거나 확신이 낮거나 자유로운 본문·인자가 필요하면 Qwen 본체가 생성합니다. 판단기를 실행할 RAM이 부족하거나 오류가 나도 본체로 이어갑니다.

판단기는 관찰하지 않은 ref·경로·해시·입력값을 만들지 않습니다. 상신·결재·인증·삭제·발송 등의 후보를 직접 실행 경로에 넣지 않습니다. 최종 처리는 기존의 대상·사용자 요청·실제 확인창·결과 목록 검증을 거칩니다. 같은 작업 반복 방지와 작업 폴더 제한도 유지합니다.

## 시각 입력

에이전트에서 작업 폴더의 PNG/JPEG/GIF/WebP를 `read_image`로 읽습니다. 파일명만 보고 그림 내용을 답하지 않으며, 실제 이미지 블록을 본체에 전달합니다. 이미지 속 지시문은 자료입니다. 한글 문서 탭의 파일 열기는 계속 HWP/HWPX용입니다.

이미지가 필요할 때 본체를 일치하는 `mmproj`와 함께 시작합니다. 이때 판단기 프로세스를 먼저 종료해 두 모델과 시각 프로젝터가 동시에 상주하지 않게 합니다. 이미지가 없는 독립 요청에는 텍스트 실행으로 돌아갑니다. 같은 작업의 도구 루프에서는 이미지를 문맥에 유지하며, 새 요청에서 그림이 필요하면 파일을 다시 읽습니다.

이미지당 최대 1,024 토큰을 예약하며, 텍스트와 이미지 예약량을 합쳐 입력 문맥을 제한합니다. 본체의 내부 추론 예산은 64토큰입니다. 10MB를 넘는 이미지는 읽지 않습니다. 텍스트 전용 나래1·2·3에 이미지를 넘기면 지원하지 않는다는 오류를 표시합니다.

스캔 PDF 전체 자동 완독이나 스크린샷 좌표로 임의 UI를 클릭하는 기능까지 구현한 것은 아닙니다. PDF의 글자 추출·페이지 렌더링·이미지 분석은 각각 실제 수행 범위를 확인해야 합니다. 브라우저 업무에는 현재 관찰한 DOM ref를 사용합니다.

## 가중치와 실행기

- 본체 원본: `Qwen/Qwen3.5-2B`, revision `15852e8c16360a2fea060d615a32b45270f8a8fc`.
- 본체 추론: `unsloth/Qwen3.5-2B-GGUF`의 고정 Q4_K_M와 F16 프로젝터.
- 판단기: `LiquidAI/d1-2B-GGUF`, revision `e968f6575f0d4fad928312d7af15cad90fd365c0`의 Q4_K_M. 판단기 가중치는 사전학습 원본을 유지합니다.
- 실행기: 공식 llama.cpp `b11960`. ZIP과 실행 파일 SHA256을 검사합니다.
- 모델 설치: 본체·학습 어댑터·프로젝터·판단기 네 파일의 크기와 SHA256을 모두 검사합니다.

앱을 새로 실행한 뒤 처음 모델을 켤 때 네 파일을 검증합니다. 같은 프로세스에서 모드만 전환할 때는 실제 경로·파일 식별값·크기·수정 시각·변경 시각이 모두 같은 파일의 검증 결과를 재사용합니다. 파일이 바뀌면 다시 해시를 검사하며, 검증 도중 변경돼도 실행을 거절합니다.

본체의 Office LoRA는 별도 BF16 원본에서 실제 최적화를 수행합니다. 마지막 전체 어텐션 블록(23번)의 q/k/v/o와 gate/up/down에 rank 16, alpha 32를 적용하며 학습 파라미터는 638,976개입니다. 앞 23개 블록은 BF16으로 동결하고 인과 마스크·MRoPE를 보존한 중간 결과를 캐시합니다. AVX2 CPU의 역전파를 위해 마지막 블록과 동결 출력 헤드, LoRA는 FP32로 계산합니다. 전체 계산과 캐시 계산의 손실 및 미래 토큰 교란을 검사한 후 학습합니다. 시각 인코더는 이 텍스트 SFT에서 학습하지 않습니다.

학습 자료는 나래3의 합성 TRAIN 자료에서 가져온 7가지 업무 유형과 새 문서 도구 사례입니다. 실제 공문·쪽지·학생 정보·인증정보를 학습 자료에 넣지 않습니다. 프롬프트나 화면 규칙의 변경을 가중치 학습으로 기록하지 않습니다. 실제 학습 단계·텐서 변화·해시·검증 결과는 별도 학습 보고서를 따릅니다.

Qwen과 Office LoRA는 Apache-2.0, d1은 LFM Open License v1.0을 따릅니다. 원문은 `resources/model-licenses/Narae4-LICENSE.txt`에 있습니다. 앱의 MIT가 모델 이용조건을 대신하지 않습니다.

## 검증 범위

새 모델은 미리보기로 취급합니다. 도구 계약 테스트, 학습에 넣지 않은 다음 행동 평가, 실제 한글 엔진의 생성·수정·PDF 출력, 원본 그림 분석, 실제 에듀파인 조회를 구분해 기록합니다. 모의 업무 성공은 실제 학교의 상신이나 발송 성공을 뜻하지 않습니다. 기존 모델의 추천과 사용자 선택을 기능 추가만으로 자동 변경하지 않습니다.
