# 나래4 교무 CLI와 추가 학습 검증

0.13.0-preview.18에서 소통메신저, 에듀파인 공문 본문·첨부·진행 상태·기안, 나이스 연가·조퇴, 한글 문서를 나래4 로컬 에이전트로 호출하는 CLI를 추가했다. 앱과 같은 `runAgent` 및 교무 도구를 사용한다. 기본 실행 가중치는 **Narae4-Qwen3.5-2B-Office-LoRA-v1**이다. 이번 추가 학습 후보 v2는 평가가 낮아져 기본으로 채택하지 않았다.

```powershell
narae-gyomu office agent-status
narae-gyomu office agent D:\Codex\tmp\요청.json --result D:\Codex\tmp\결과.json
```

JOB의 필수 값은 prompt와 기존 workspace다. model 기본값은 narae4이며 설치된 로컬 모델을 사용한다. 문서 변경·브라우저 조작은 allowChanges:true일 때 실행한다. 기본 조회 작업에서 변경 승인을 기다리는 창은 띄우지 않는다. 계약과 예시는 [나래4 CLI](../skills/narae-hangul-office/references/narae4.md)에 있다.

## 업무 흐름 보완

- 소통메신저는 받은·보낸·미열람 쪽지함을 목록과 본문에서 일치시킨다. 요청한 본문을 순차 조회하며 실패 항목은 미확인으로 남긴다.
- 문서진행은 현재 목록의 상태·현재 결재자를 근거로 정리한다. 목록 확인과 본문·첨부 요약을 구분한다.
- 공문은 한 건씩 WXS 읽기 대기→같은 제목 열기→본문·첨부 결과→닫힘 확인을 거친다. 첨부는 남은 청크를 이어 읽는다. 실제 다음 페이지 버튼을 사용하며 동일 제목이나 바뀌지 않은 페이지를 임의 처리하지 않는다.
- 요약 단계에는 본문과 첨부의 실제 텍스트를 문서별로 모아 전달한다. 목록 조회 기간을 제출 기한으로 바꾸거나 첨부 파일명만 나열하는 문제를 줄인다. 시각 확인 대기·원본 변경·읽기 실패는 미확인이다. 자료가 모델 문맥을 넘으면 요약 완료로 처리하지 않는다.
- 이미 열린 기안의 임시저장도 인식한다. 저장 시도 후 같은 초안을 다시 읽고 동일 저장·본문 입력을 반복하지 않는다. 불명확한 저장은 미확인으로 남긴다.
- 연가와 조퇴 모두 실제 요청한 날짜·시간·사유를 대조하는 준비 경로를 사용한다. 후속 메시지의 명시적 사유가 이전 사유보다 우선한다. 다른 복무 종류 전체를 구현한 것은 아니다.
- 문서·그림 요청에는 관련 도구를 제공하고, CLI 문서 읽기는 중복 없는 compact 결과를 사용한다. 문서 본문의 ‘자료 검토’ 같은 주제로 생성 완료 판정이 막히지 않게 했다. 단일 시각 변경은 저장 해시·새 본문·다른 문단 텍스트를 대조한 뒤 끝내 반복 편집을 막는다.

## 실제 가중치 추가 학습

학습 40개(새 교무 예시 32개와 v1 TRAIN 유지 8개), 검증 8개를 사용했다. 실제 학교·개인 자료와 Codex 세션 원문은 학습에 넣지 않았다. 다른 세션에서 확인된 절차와 모의 시험의 구분을 개발 점검에 참고했다.

v1 HF 어댑터를 이어서 마지막 전체 어텐션 블록의 LoRA 파라미터 638,976개를 20회 업데이트했다. 약 38분이 걸렸으며 14개 텐서의 변경을 확인했다. 시각 인코더와 판단기는 학습하지 않았다. 전체 계산과 캐시 계산의 loss가 같고 미래 토큰 교란 차이는 0이었다. HF→GGUF 변환 후 14개 텐서가 비트 단위로 일치했다.

| 평가 | 기존 v1 | 추가 후보 v2 |
|---|---:|---:|
| 교무 직접 다음 행동, 고정 합성 16개 | 5/16 | 4/16 |
| 기존 문서 평가 8개 | 과거 기록 7/8 | 6/8 |
| 이번 자료의 검증 loss | 0.4483 | 0.3976 |

문서 평가의 기존 기록은 max_tokens 1024, 후보는 768이다. 후보의 실패는 길이 제한이 아닌 완료 응답의 판단 오류였다. 같은 조건으로 비교한 교무 직접 판단도 낮아져 **v2를 채택하지 않고 기존 v1을 유지**한다. loss 하락을 업무 정확도 향상으로 안내하지 않는다. 실행기가 후보를 제한한 업무 흐름 시험과 모델 단독 판단 점수도 구분한다.

시작·종료 어댑터 해시, 데이터 동결, 학습 설정·텐서 변화와 원본 결과는 [추가 학습 재현](../experiments/narae4-gyomu-v2-20261031/README.md) 및 [요약 JSON](../experiments/narae4-gyomu-v2-20261031/results/summary.json)에 있다. 후보 가중치는 로컬 학습 폴더에 보관하며 소스 배포에 포함하지 않는다.

## 검증 결과

| 범위 | 결과 |
|---|---|
| 오피스 자동 테스트 | 210/210 |
| 공통 CLI 자동 테스트 | 18/18 |

| 실제 로컬 가상 나이스 브라우저 | 연가·조퇴 2/2, 입력값·결재선·미상신 확인 |
| 실제 한글 엔진 | HWPX 생성·시간 변경·재읽기, 나머지 문단 텍스트 보존 확인 |
| 실제 그림 입력 | 가상 안내의 장소·비용·시각 확인 |

공문 2건의 기한 누락, 문서 생성 후 반복 시도와 문맥 초과를 수정한 뒤 해당 사례를 재검증했다. 시간 변경은 수정 후 한 번의 편집 호출과 재읽기로 완료되었으며 오류가 없었다. 사례별 실행 출처는 [업무 흐름 결과](../experiments/narae4-gyomu-v2-20261031/results/workflows-installed.json)에 남겼다.

소통메신저·에듀파인·WXS는 가상 도구 관찰, 나이스는 외부 요청을 차단한 로컬 가상 화면이다. 한글 파일과 그림은 실제 엔진을 사용했다. 이번 검증은 실학교 로그인·메시지 발송·기안 상신·복무 상신의 성공 기록이 아니다. 실제 업무에서는 현재 로그인·문서·결재선·첨부·결과 목록을 각 도구로 확인해야 한다.
