# 나래4 도구 활용 보완 검증

나래 한글 오피스 0.13.0-preview.19. 기존 나래4 v1 가중치를 사용하며 이번 작업에서 가중치를 추가 학습하지 않았다. 앱과 CLI의 저장 문서 실행 경로를 공통화하고 도구 인자·원문 근거·작업 완료 검증을 보완했다.

| 영역 | 변경 전 필수 검사 | 보완 후 |
|---|---:|---:|
| 소통메신저 | 1/2 | 2/2 |
| 공문 열람·요약 | 1/2 | 2/2 |
| 진행 문서 확인 | 2/2 | 2/2 |
| 기안 임시저장 | 1/2 | 2/2 |
| 한글 파일 | 2/2 | 2/2 |
| 나이스 복무 | 2/2 | 2/2 |

기본 12건의 필수 조건은 43/49→49/49다. 대화의 실제 보낸 사람·시각 유지, 실제 긴 텍스트 첨부의 연속 읽기, 신규 기안 제목·본문 입력 후 임시저장도 최종 설치본에서 3/3 통과했다.

저장 문서의 제목·본문·용지·여백·표·그림과 새 사본 저장 인자를 연결했다. 문단과 첨부는 실제 nextOffset으로 이어 읽고 파일 해시가 달라진 결과를 섞지 않는다. 단순 시각 변경은 실제 유일한 문단과 사용자 변경값으로 작업 인자를 제한하고 저장 해시·다른 문단 보존까지 대조한다. 필수 안내문은 notice로 저장 본문에 포함한다.

소통·공문 요약은 모델이 실제 원문 구절 ID를 선택하고 실행기가 원문과 조회 조건·미확인 항목을 표시한다. 임의의 읽음·업무 완료 상태나 조회 기간을 자유 문장으로 만들지 않는다. 구절 선택 실패 시 확인 원문 발췌임을 표시한다. 이는 원문 근거 요약 방식이며 모든 긴 문서의 추상 요약 능력이 같다는 뜻은 아니다.

기존 기안은 저장 1회·상태 조회 2회(전/후)로 종료했고 신규 기안은 사용자 원문 입력→재조회→저장 확인으로 연결했다. 입력 전 저장으로 대체하지 않는다. 현재 창의 제목·핸들, 명시한 본문과 기존 경로를 확인한다. 본문 보존 표현이나 긴 제목·본문 때문에 임시저장 의도를 놓치던 분기를 고쳤다.

자동 시험 222개와 vendor 4개 원본·536개 파일 대조를 통과했다. 실제 파일 제목·안내문·이어 읽기·사본 저장, 원문 구절 검증, 반복 오류 중단, 변경 추적 문서의 live 읽기 등 회귀 검증을 포함한다. 자동 시험과 별도로 실제 나래4를 사용했다. 기본 12건은 최신 통과 결과를 합친 것이며 단일 최초 실행 12/12가 아니다. 구현 도중의 복제 경로·훈련 표시·수정 개수·신규 기안 실패와 한 번의 모델 통신 오류는 원 기록에 보존했다. 보완 후 신규 기안·긴 첨부·대화 3건은 한 번의 최종 묶음 실행으로 검증했다. 최종 원 자료: D:/Codex/training/narae4-tool-parity-20261031\summary.json.

학교 서비스는 모의 도구 응답·외부 통신 차단 로컬 화면이며 HWPX와 저장 텍스트는 실제 엔진이다. 실제 학교 공문 저장·전송·상신은 수행하지 않았다. 신규 기안의 실제 WXS 화면 배치·서버 첨부 바이트 검증과 다른 복무 종류는 이 결과의 범위에 없다. Codex와 같은 추론 성능을 증명한 것은 아니다.

현재 실행 중인 GUI는 재실행 후 새 코드를 읽는다. CLI 설치 버전과 모델 선택은 agent-status로 확인한다.
