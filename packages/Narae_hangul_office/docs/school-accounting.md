# 학교회계 품의 등록·저장·정리 (preview.24)

지역별 업무포털·메신저·카카오 연결과 기존 나래4 v1 가중치를 유지한다. 이 변경은 학교회계 도구와 실행 절차의 추가이며 새 가중치 학습이 아니다. 나래4가 작성안을 만들고, 이후 단계는 실제 도구 결과에서 고정한 값·ID·해시로 실행한다.

나래4에 “학교회계 품의목록 조회해”, “품의 00007 상세 읽어줘”, “품의 예산 후보 조회해”, “품의를 등록하고 저장해”라고 요청한다. 제목·개요·요구일자·완료요구일자·정확한 예산 산출내역·품목의 수량과 단가를 제공한다. 없는 값은 질문으로 남기며 기존 문서의 값으로 채우지 않는다. 필드 이름과 값을 한 줄씩 적으면 제목의 괄호·공백과 품목명을 그대로 제한해 입력한다.

```text
학교회계 품의를 등록하고 저장해.
제목: 합성 재료 구입
개요: 합성 예시입니다.
요구일자: 2036-04-01
완료요구일자: 2036-04-12
예산 산출내역: 실제 화면에서 확인한 정확한 산출내역
품목: 색종이, 수량 3, 단가 2400원
첨부 "D:/Codex/workspaces/합성 첨부.pdf"
결재요청 및 상신은 하지 마.
```

시험 등록을 끝낸 뒤 지우려면 “저장·검증 후 삭제해서 정리해”를 명시한다. 제목에 ‘삭제’라는 말이 있는 것만으로 삭제를 허용하지 않는다.

공통 CLI는 `narae-gyomu tool call edufine.requisition --args-file D:\Codex\tmp\품의요청.json`을 사용한다. 오피스 도구명은 `gyomu_edufine_requisition`이다. 자세한 인자와 공식 자료 링크는 동봉한 [학교회계 절차](../vendor/narae-gyomu/packages/narae_gyomoo_portal/skills/narae-gyomu-edufine/references/school-accounting.md)에 있다.

현재 구현: 목록·조건 조회, 문서번호/제목/연도에 묶인 상세 읽기, 정수 원 단위 검산, 빈 신규 등록 입력, 실제 후보 키로 예산 선택, 품목 입력, 원본 첨부, 저장 확인창 처리, 서버 재조회 후 기본정보·예산·품목 대조, 첨부 재다운로드 해시 검증, 이 작업에서 저장한 시험 품의 삭제와 서버 부재 확인. 여러 열린 Nexacro MDI 창을 경로별로 구분한다.

실환경 보완: 시작 공지창 닫기, 좁은 창의 좌우 메뉴 접기, 느린 업무 선택 대기, `fill` 대신 실제 `type`+Tab으로 내부 값 확정, 달력 숫자 입력, 셀 편집 후 대기 컨트롤 읽기, 자동 합산 요구금액의 중복 입력 방지, 표준 NAA/FAA 확인창과 `btnCancle` 철자 처리. 신규 입력 ID/digest와 최종 동작 receiptId를 구분한다. 클릭·성공 안내·세션 연장 응답만으로 완료를 보고하지 않는다. 현재 프로세스의 동작 기록 없이 저장·삭제를 재실행하지 않는다.

한계: 현재 렌더링된 행 범위이며 전체 건수·가상 스크롤 밖 행은 미확인이다. 결재요청·상신, 임의 기존 품의 삭제, 실제 구매·지급은 지원하지 않는다. 다수 예산·단위 선택·화면 밖 품목의 전체 처리는 실환경 검증 범위 밖이다. 금융 품의 상신을 일반 WXS 공문 상신으로 대신하지 않는다.

검증: 2026-11-01 사용자 승인 범위의 1원짜리 합성 시험 품의로 저장·서버 재조회·첨부 바이트/SHA-256 대조·삭제 후 부재를 확인했다. 마지막 시험은 설치된 나래4 v1과 실제 실행기를 사용해 20단계, 131.296초에 개입 없이 완료했다. 시험 품의는 모두 정리했다. 결재요청·상신·실제 집행은 실행하지 않았다. 실제 학교 원본·예산·사람 이름·세션 자료는 이 문서·공개 테스트·훈련자료에 포함하지 않는다.
