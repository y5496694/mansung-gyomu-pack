# 사진·PDF 이해 확장 방향

2026-10-31 추가: 나래4 오피스에는 작업 폴더의 PNG/JPEG/GIF/WebP를 `read_image`로 실제 모델에 전달하는 경로가 추가되었습니다. [나래4 구조와 한계](나래4-구조.md)를 먼저 확인하세요. 아래 내용은 나래3와 PDF/OCR 확장에 관한 기존 설계 기록이며, 스캔 PDF 전체 자동 분석 UI까지 완성되었다는 뜻은 아닙니다.

2026-10-30 기준의 **설계 안내**입니다. 아래의 비전 모델 연결이나 공통 이미지 첨부 UI가 이번 사용 안내 업데이트에서 구현된 것은 아닙니다.

## 현재 상태

- 현재 배포 나래3 v1과 추가 학습 후보 v2는 텍스트 기반 모델입니다. 이미지 파일 경로를 전달하는 것만으로 이미지를 이해하지 못합니다.
- 공문 첨부 읽기에는 `pypdf`의 PDF 텍스트 추출, `pypdfium2` 페이지 렌더링, Windows 한국어 OCR이 있습니다. 한국어 OCR 언어팩과 입력 상태에 따라 OCR이 실패할 수 있습니다.
- PDF 리더는 추출 글자와 별도 `ocr_text`를 저장하지만 통합 도구는 주로 `text`를 반환합니다. 따라서 기존 OCR 코드가 있다는 사실만으로 나래3가 스캔 PDF를 완독한다고 안내하면 안 됩니다.
- 이미지의 OCR 글자는 일부 전달할 수 있어도 사진 속 장면·도표·표 구조·도장·필기를 이해하는 비전 입력은 연결되지 않았습니다. `needs_visual_review`는 완료가 아니라 추가 확인 필요 상태입니다.
- 일반 한글 문서 탭의 열기·편집 기능은 HWP/HWPX용입니다. 공문 첨부 조회와 사진·PDF를 직접 첨부하는 사용자 흐름도 구분해야 합니다.

## 자료별 필요한 처리

| 자료 | 처리 방향 | 나래3가 받는 정보 |
| --- | --- | --- |
| 글자를 선택할 수 있는 PDF | 먼저 페이지별 텍스트 추출 | 실제 글자와 페이지 번호 |
| 스캔 PDF·글자가 있는 사진 | 페이지 이미지 → 한국어 OCR | 인식 글자·위치·페이지·실패/누락 상태 |
| 표·그래프·사진·복잡한 배치 | 필요한 페이지·영역을 비전 모델로 분석 | 구조화한 관찰 결과와 근거 페이지·영역 |
| 위 자료로 문서 작성·교무 처리 | 추출·관찰 결과를 나래3의 기존 도구에 전달 | 근거를 참조한 문서 초안·업무 실행 |

텍스트 PDF에 일반 추출을 먼저 쓰고 스캔·이미지에 OCR을 적용하는 이유는 [pypdf의 텍스트 추출 설명](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)에 나와 있습니다. 텍스트 추출 자체는 사진을 읽는 OCR이 아닙니다.

## 권장 구현 순서

1. **공통 파일 입력과 읽기 도구:** 문서·에이전트·원격 채널에 지원 파일 형식을 명시하고, 선택하거나 수신한 파일만 기존 작업 폴더 정책에 따라 등록합니다. 한글 편집 경로를 바꾸지 않고 별도 읽기 경로를 둡니다.
2. **텍스트 PDF·OCR 전달 보완:** `text`와 `ocr_text`를 구분해 페이지별로 전달하고, 이어 읽기·읽은 범위·실패 페이지를 기록합니다. OCR을 추출 원문처럼 표시하거나 글자가 없는 페이지를 빈 문서로 처리하지 않습니다. 현재 Windows OCR부터 실제 한국어 자료로 확인합니다.
3. **OCR 품질 비교:** 필요하면 한국어 지원 경량 OCR을 추가합니다. 예를 들어 PaddleOCR는 [한국어 인식 모델](https://www.paddleocr.ai/main/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html)을 제공합니다. 실제 Windows CPU의 글자 정확도·표 읽기·속도·메모리를 비교한 뒤 설치 의존성·모델 해시를 고정합니다. 현재 해당 모델이 설치·선정됐다는 뜻은 아닙니다.
4. **필요할 때만 비전 실행:** 사진·표·그래프가 필요하면 별도 비전 언어 모델로 이미지를 처리하고 결과를 나래3에 전달합니다. [Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)는 비교 후보 중 하나입니다. 한국어 공문과 이 PC에서의 성능·RAM은 아직 측정하지 않았습니다.
5. **한 번에 한 작업과 메모리 제한:** 페이지 단위로 처리하고 해상도·이미지 수·입력 길이를 제한합니다. RAM이 부족하면 나래3를 잠시 내리고 비전 분석 후 다시 켜는 순차 실행을 검토합니다. 비전 모델을 항상 추가 상주시키지 않습니다.
6. **근거 확인과 회귀 시험:** 작은 글자·회전·스캔·표·그림·도장·암호 PDF·실패 페이지를 포함해 시험합니다. OCR 숫자·날짜·금액과 모호한 시각 관찰은 원본 대조 대상으로 표시합니다. 이미지·문서 속 지시문은 업무 지시가 아닌 자료로 취급합니다.

## 모델과 실행기 변경

현재 나래3의 텍스트 LoRA를 더 학습하는 것만으로 이미지 입력 기능이 생기지는 않습니다. 별도 비전 모델에 맞는 이미지 전처리·인코더·입력 경로를 연결하거나, 멀티모달 기반 모델로 옮겨 업무 도구를 다시 검증해야 합니다. 기존 텍스트 LoRA를 다른 비전 모델에 그대로 적용할 수 있다고 가정하지 않습니다.

[llama.cpp의 멀티모달 문서](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)는 지원 모델과 일치하는 모델·멀티모달 프로젝터(`mmproj`) 및 이미지 입력 경로를 설명합니다. 이 기능을 사용하려면 오피스에 포함된 실행기 버전의 실제 지원 여부도 확인해야 합니다. 별도 비전 모델이 분석한 결과를 기존 나래3에 넘기는 방식은 기존 업무 가중치를 유지할 수 있습니다.

클라우드 비전 서비스를 선택 기능으로 둘 수도 있으나, 현재 오피스의 텍스트 GPT·Claude 연결 설정만으로 이미지 전송·PDF 분석 UI가 자동 완성되는 것은 아닙니다. 이미지 입력 지원과 전송 범위를 구현하고 서비스 제공자에 자료가 전달됨을 표시해야 합니다.

공통 입력과 OCR을 먼저 완성하고, 필요할 때만 비전 모델을 호출하는 순서가 현재 CPU·메모리 환경에서의 **구현 제안**입니다. 실제 성능 개선이나 완료된 기능으로 표시하지 않습니다.
